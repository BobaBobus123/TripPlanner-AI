# Перші вимірювання AI-сценарію (ПР15)

Для вимірювання реального провайдера потрібні конфігурація моделі та API-ключ користувача. У цьому середовищі платних запитів до реального API не виконували, тому вартість і затримку провайдера не вигадуємо.

|---|---|---:|---:|---:|---|---|---|---|
| — | OpenAI-сумісний провайдер | — | — | — | Не застосовується (запит без потокової передачі) | — | — | заповнити після локального вимірювання на реальному API |
| 2026-11-27 | Офлайн-оцінювання mock, k=3 | 24 запуски сценаріїв | Не застосовується (це не мережева затримка) | Не застосовується | Не застосовується | Оцінки mock, не лічильник провайдера | 0 (без реального API) | 8/8 pass^k |

Для вимірювання реального API виконайте щонайменше 10 запитів на фіксованих кейсах і зафіксуйте вибрану модель, тип endpoint (без URL із секретами), час виконання, затримку, кількість токенів і вартість за актуальним тарифом. Не зберігайте API-ключ, необроблений prompt чи дані користувача. TTFT вимірюється лише після появи справжнього контракту потокової передачі.

Ціни задаються параметрами `INPUT_COST_PER_MILLION_TOKENS` і `OUTPUT_COST_PER_MILLION_TOKENS` у USD за мільйон токенів. Перед кожним запитом перевірка бюджету резервує консервативну оцінку на основі довжини prompt і `MAX_OUTPUT_TOKENS`; фактична сума записується в лог для подальшого порівняння. Тариф потрібно вручну оновлювати відповідно до вибраного провайдера.
