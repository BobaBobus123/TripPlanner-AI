# ADR-0001: Синхронне створення плану у walking skeleton

- Статус: замінено для поточного продуктового сценарію
- Дата: 2026-11-27

## Контекст

На ПР14 локальний mock був швидким, тому синхронний контракт давав найменший робочий каркас. Після появи повного сценарію користувача потрібні збереження задач, відновлення після оновлення сторінки та чесні оновлення під час генерації.

## Рішення

`POST /api/v1/jobs` повертає `202 Accepted` і довговічний ідентифікатор задачі. Worker обробляє її окремо, а клієнт отримує статус через API та SSE з `Last-Event-ID`. Завершений результат і переходи станів зберігаються у PostgreSQL.

## Наслідки

- Потрібні окремий worker і PostgreSQL у production; локально лишається простий in-memory режим із worker у процесі.
- Lease та явний стан `interrupted` не допускають непомітного повторного платного виклику після аварії.
