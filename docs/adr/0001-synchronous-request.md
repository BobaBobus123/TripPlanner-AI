# ADR-0001: Синхронное создание плана в walking skeleton

- Статус: принято для ПР14
- Дата: 2026-11-27

## Контекст

В ПР14 используется быстрый локальный mock. Очередь фоновых задач, polling, отмена и SSE увеличили бы объём каркаса до появления измеренной потребности.

## Решение

`POST /api/v1/plans` синхронно возвращает результат. Перед внедрением реального провайдера в ПР15 измеряются latency и TTFT; по этим данным решение пересматривается.

## Последствия

- Простой HTTP-контракт и лёгкая демонстрация с чистого клона.
- Длинные вызовы позже потребуют `202`, статуса задачи, результата и отмены; это будет отдельное изменение API.
