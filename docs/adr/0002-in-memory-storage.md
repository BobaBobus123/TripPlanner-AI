# ADR-0002: Сховище в пам’яті для ПР14

- Статус: замінено для production
- Дата: 2026-11-27

## Контекст

Початковий walking skeleton мав працювати без налаштування зовнішньої бази. Повний сценарій із користувачами, чергою, SSE та відновленням потребує спільного сховища між вебпроцесом і worker.

## Рішення

Використовувати `MemoryTripPlannerStore` локально та в тестах. Для production застосовувати `PostgresTripPlannerStore`, що реалізує той самий async-контракт; унікальність ідемпотентності, задачі, сесії та події зберігаються в PostgreSQL.

## Наслідки

- Локальний запуск залишається доступним без секретів, але його дані зникають після перезапуску процесу.
- Production потребує спільного `DATABASE_URL`; worker не запускається в вебпроцесі.
- Реальне підключення до Railway треба перевірити в цільовому проєкті до публічного запуску.
