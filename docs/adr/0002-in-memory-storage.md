# ADR-0002: Локальне та production-сховище

- Статус: оновлено для ПР17
- Дата: 2026-11-27

## Контекст

Застосунок має запускатися без зовнішніх облікових записів, зберігаючи локальні облікові записи й подорожі після перезапуску. Production потребує спільного сховища між вебпроцесом і worker.

## Рішення

Використовувати `SQLiteTripPlannerStore` локально та `MemoryTripPlannerStore` у швидких ізольованих тестах. Для production застосовувати `PostgresTripPlannerStore`, що реалізує той самий async-контракт; унікальність ідемпотентності, задачі, сесії та події зберігаються в PostgreSQL.

## Наслідки

- Локальний запуск не потребує секретів; файл `data/tripplanner.sqlite3` зберігає стан між перезапусками процесу.
- Production потребує спільного `DATABASE_URL`; worker не запускається в вебпроцесі.
- Реальне підключення до Railway треба перевірити в цільовому проєкті до публічного запуску.
