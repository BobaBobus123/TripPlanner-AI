# Контракт API ПР14

Базова адреса: `/api/v1`. Форми й відповіді JSON використовують моделі Pydantic з `extra="forbid"`. Усі відповіді містять заголовок `X-Request-ID`. Можна передати власний ID з літер, цифр, `.`, `_`, `-` (1–128 символів); інакше сервер створить UUID.

## `GET /health`

Перевірка доступності й готовності без виклику провайдера та без розкриття секретів.

```json
{
  "status": "ok",
  "checks": {
    "storage": "memory",
    "provider": "mock"
  }
}
```

`GET /health/live` і `GET /health/ready` доступні для окремих перевірок системою оркестрації.

## `POST /api/v1/plans`

Синхронно створює план і повертає HTTP `201 Created`. Заголовок `X-Owner-ID` обов’язковий. Наразі це демонстраційний ідентифікатор власника, а не механізм автентифікації.

```json
{
  "destination": "Львів",
  "start_date": "2027-05-10",
  "end_date": "2027-05-12",
  "currency": "UAH",
  "budget": 12000,
  "traveler_count": 2,
  "interests": ["архітектура"]
}
```

Відповідь містить `id`, нормалізовані вхідні дані, маршрут на кожен календарний день, `missing_data`, `source` (`main`, `mock` або `recorded`) і `created_at`. Модель і mock не стверджують, що знають актуальні ціни, погоду чи години роботи, якщо немає перевірених джерел. Усі дати перевіряються на відповідність періоду подорожі; орієнтовна вартість — на відповідність бюджету.

Для режиму OpenAI-сумісного провайдера запитується JSON-об’єкт за єдиною схемою Pydantic. Для виправлення невалідної відповіді виконується щонайбільше одна повторна спроба; початковий текст моделі не зберігається й не повертається клієнту. Ключ, модель, endpoint і вартість токенів налаштовуються через змінні середовища.

## `GET /api/v1/plans/{plan_id}`

Повертає план лише власнику, вказаному в `X-Owner-ID`. Неіснуючий план і план іншого власника повертають однаковий код `404`, щоб не розкривати наявність чужих даних.

## Формат помилки

```json
{
  "error": {
    "code": "invalid_request",
    "message": "Не вдалося перевірити дані запиту.",
    "retryable": false,
    "request_id": "demo-request-01",
    "fields": ["end_date"]
  }
}
```

Каталог кодів: `invalid_request` (422), `not_found` (404), `rate_limited` (429), `daily_budget_exceeded` (429), `provider_unavailable` (503), `provider_timeout` (504), `invalid_output` (502), `internal` (500). Для помилки, яку можна повторити, за наявності інтервалу відповідь також містить `retry_after` і HTTP-заголовок `Retry-After`. Відповіді не містять traceback, значень користувача чи подробиць винятку.

## Синхронне рішення

На ПР14 не створюються асинхронні завдання, тому `202 Accepted`, окремі статус/результат і скасування тут не потрібні. Після впровадження реального провайдера вимірювання затримки на ПР15 допоможуть визначити, чи потрібен контракт із фоновими завданнями.

Опис OpenAPI доступний під час роботи застосунку за адресою `/openapi.json`; знімок контракту буде додано на ПР19.
