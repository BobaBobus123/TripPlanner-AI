# TripPlanner AI

Навчально-практичний AI-асистент для планування подорожей.

## Поточний результат

Реалізовано український шлях користувача: реєстрація/вхід → покрокове заповнення → довговічне завдання → реальні повідомлення етапів через SSE → результат і список збережених подорожей. Для локального запуску без секретів використовується mock-провайдер і тимчасове сховище в пам’яті. Для довговічного зберігання потрібен PostgreSQL.

## Локальний запуск

Потрібен Python 3.11 або новіший.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
uvicorn tripplanner.main:app --reload
```

Відкрийте `http://127.0.0.1:8000/`. Інтерфейс Swagger UI доступний за адресою `http://127.0.0.1:8000/docs`.

На сторінці `/register` створіть обліковий запис, підтвердьте електронну пошту за посиланням і перейдіть на `/login`. У локальному режимі `EMAIL_BACKEND=development` лист не надсилається — одноразове посилання показується в інтерфейсі лише для демонстрації. Після входу виконайте кроки «Подорож» → «Побажання» → «Перевірка» та натисніть «Створити план». Черга, генерація й перевірка відображаються за подіями worker, а не за фіктивним таймером.

Під час першого відкриття зареєструйтеся, підтвердьте адресу та увійдіть. Пошта має бути підтверджена до створення сесії. Локальний режим `memory` зберігає облікові записи, сесії та подорожі лише до завершення процесу; worker запускається разом із вебзастосунком. Інтерфейс відновлює поточну задачу після оновлення сторінки, поки працює сервер.

Після входу доступні окремі сторінки: огляд `/dashboard`, список `/trips`, створення `/new` і деталі подорожі `/trips/{id}`. Посилання можна відкривати напряму й оновлювати; активна задача відображається на своїй сторінці та оновлюється в реальному часі.

## Режим AI

За замовчуванням `PROVIDER=mock`: це локальний демонстраційний генератор, він не викликає зовнішній AI API. Щоб дозволити власнику перемикати режим на сторінці огляду:

1. Створіть локальний `.env` на основі `.env.example` (якщо файл уже існує, доповніть його; цей файл не додається до Git).
2. Задайте `APP_ADMIN_EMAIL` як адресу облікового запису власника.
3. Для OpenAI додайте `OPENAI_COMPAT_API_KEY`, `OPENAI_COMPAT_MODEL` та актуальні `INPUT_COST_PER_MILLION_TOKENS` і `OUTPUT_COST_PER_MILLION_TOKENS`.
4. Перезапустіть сервер і увійдіть під вказаною адресою. На огляді з’явиться глобальний перемикач OpenAI/mock.

Ключ зберігається лише на сервері. У режимі OpenAI сервер передає провайдеру напрямок, дати, бюджет, кількість мандрівників та побажання з форми. Режим `memory` очищує глобальний вибір і історію після перезапуску; у PostgreSQL вибір режиму зберігається між запусками. Фактичні погода, ціни та години роботи не перевіряються.

## Перевірки

```powershell
python -m pytest
```

За замовчуванням використовується лише детермінований mock-провайдер; платні API не викликаються. Щоб під’єднати сумісний з OpenAI endpoint, задайте `PROVIDER=openai_compat`, `OPENAI_COMPAT_API_KEY`, URL, модель і актуальні ціни токенів. Конфігурація задається змінними середовища; приклад наведено у файлі [.env.example](.env.example).

## PostgreSQL та Railway

У Railway створіть PostgreSQL і додайте до **вебсервісу й окремого worker-сервісу** ті самі змінні:

- `APP_ENV=production`
- `STORAGE_BACKEND=postgres`
- `DATABASE_URL` — посилання на приватну URL-змінну Railway PostgreSQL; не додавайте її до репозиторію.
- `SESSION_COOKIE_SECURE=true`
- `EMAIL_BACKEND=smtp`, `EMAIL_FROM`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_STARTTLS=true` і публічний `PUBLIC_BASE_URL=https://...`; SMTP username/password задайте як secret variables.
- `EMAIL_VERIFICATION_TTL_MINUTES=30` або інший обґрунтований строк дії листа.
- `PROVIDER=mock` для безкоштовного тесту або конфігурація `openai_compat` з актуальними цінами й секретним ключем.

Команда вебсервісу:

```text
uvicorn tripplanner.main:app --host 0.0.0.0 --port $PORT
```

Створіть другий Railway-сервіс із цього самого репозиторію та спільними змінними, але задайте команду:

```text
python -m tripplanner.worker
```

Схема створюється ідемпотентно під час запуску вебзастосунку й worker. Вебсервіс приймає запити та SSE, worker виконує задачі; обидва мають бачити ту саму PostgreSQL-базу. Перевірте `/health/ready` і пройдіть шлях створення/перезапуску на тестовому деплої.

Реальний деплой до Railway у цій зміні не виконувався: для нього потрібні доступ до Railway-проєкту, підключена база та SMTP-провайдер. У production задайте `EMAIL_BACKEND=smtp`, `EMAIL_FROM`, `SMTP_HOST`, публічний HTTPS `PUBLIC_BASE_URL` і SMTP-облікові дані. Паролі листів зберігайте лише в secret variables. Відновлення пароля ще не реалізовано.

Офлайн-оцінювання (без HTTP і реального API). Результати зберігаються в каталозі `eval/runs/`, який ігнорується Git:

```powershell
python -m scripts.run_eval --k 3
```

Для керованого відтворення або запису використовуйте `RECORDED_MODE=replay|record|passthrough`. Режим `record` локально зберігає хеш ключа та згенеровану відповідь. Використовуйте лише синтетичні дані й не публікуйте каталог `recordings/`.
